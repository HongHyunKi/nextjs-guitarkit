# MCP UI 검증 — 2026-09-23

대상: `http://localhost:3005/guitar-scale`, Chrome 앱을 MCP `cua_repl`로 조작.
자동화 테스트 러너가 아닌 실제 UI 조작·접근성 트리·스크린샷 검증 기록이다.

## 확인 결과

- 데스크톱: 기본 전체+스케일 표시, 스케일 필터 전환 시 비구성음 버튼 제거 확인.
- 도레미/123: 지판 표시와 구성음 목록 전환 확인. Db Major 구성음은 123 모드에서 1–7로 표시.
- 음 찾기: C Major의 스케일 밖 C# 선택 시 전체 음 표시 및 해당 위치 강조 확인. 새로고침 후 유지되고, 해제하면 이전 스케일만 모드로 복귀.
- 모바일: 390px 다크, 360px 라이트에서 지판 내부 가로 스크롤 및 줄 라벨 고정 확인. 다음 구간 이동 후 오른쪽 끝에서 다음 버튼 비활성화 확인.
- 태블릿: 768px에서 조성/스케일 설정 펼침과 지판 배치 확인.
- 프렛 범위: 슬라이더로 12–24프렛 설정, 전체 음 모드에서 6개 줄의 24프렛 버튼 확인. 새로고침 후 범위 유지.
- 저장/재생: BPM 112 입력 후 새로고침 복원. 백킹 트랙 Play → Stop 상태 전환, 재생 중 새로고침 후 Play(정지) 상태 복원 확인.

## 발견 및 수정

- 360px에서 ‘스케일’ 단어가 글자 단위로 끊김: 표시 모드 버튼에 `break-keep` 적용 후 재검증.
- 좁은 화면에서 백킹 트랙 모드/재생 버튼 글자가 끊김: 헤더 줄바꿈 허용, 버튼 줄바꿈 방지, 최소 44px 높이 적용 후 재검증.

## 검증 한계

- 실제 모바일 기기가 아닌 Chrome 반응형 에뮬레이션이다.
- 오디오 재생 상태 전환은 확인했지만 실제 출력 음정/음질은 청취 검증하지 않았다.
- 터치 스와이프의 오발음 방지, 저장소 접근 거부는 이번 UI 테스트에서 재현하지 않았다. 손상된 설정값 복구는 기존 단위 테스트 범위다.

## 이론 수정 후 추가 검증

- 768px: C# Major를 선택하고 CDE 모드에서 구성음 `C# D# E# F# G# A# B#` 확인. 지판의 1번 줄 13프렛 E#, 2번 줄 13프렛 B#도 일치.
- D Harmonic Minor: 구성음 `D E F G A Bb C#`와 지판 표기 일치. CAGED 버튼 대신 전체 포지션 안내 표시. 기존 CAGED 선택이 저장된 상태에서 새로고침해도 잘못된 포지션 강조 없음.
- C Major E 모양: 0–24프렛으로 변경. 390px에서 다음 구간 버튼을 두 번 눌러 6–10프렛으로 이동. 3번 줄 7프렛 D, 4번 줄 7프렛 A, 5번 줄 7프렛 E의 활성 강조를 스크린샷으로 확인. 2번 줄 7프렛 F#는 비구성음으로 구분.
- 390px: 접힌 설정 요약, 설정 펼침, 자연 마이너 버튼, 한국어 설명, CAGED 설명·버튼의 줄바꿈 확인. 지판의 줄 라벨은 가로 이동 시 고정.
- 자동 검증: Jest 5개 스위트·206개 테스트 통과. 과거의 프렛 범위 테스트는 출처 도표를 전사한 줄별 운지 테스트로 교체했으므로 이전 테스트 개수와 직접 비교하지 않는다. TypeScript 검사 통과. Google Fonts 접근 허용 후 프로덕션 빌드 통과.
- 잘못된 단순 음이름을 기대하던 `lib/scale-tests.ts`는 중복 레거시 스크립트여서 삭제했다. Git 이력에서 복구 가능하며, 실행 가능한 검증은 Jest로 통합했다.
